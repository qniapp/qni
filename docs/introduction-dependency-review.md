## Concrete integration finding: source attribution

The replacement's `apps/web/scripts/build-embed.sh` now embeds `SOURCE_COMMIT`, choosing `QNI_SOURCE_COMMIT`, then `GITHUB_SHA`, then the WebGPU checkout's HEAD. In a consuming repository's Actions job, `GITHUB_SHA` identifies the consumer, not the nested WebGPU checkout. Merely advancing the source ref therefore produces incorrect attribution in CI unless the caller supplies `QNI_SOURCE_COMMIT` explicitly.

The old-Qni repair passes the already-read exact WebGPU ref as `QNI_SOURCE_COMMIT` to the existing source-assets build step. `scripts/check-pages-config.mjs` requires the checkout and build attribution to use that same ref. Its regression tests run with a foreign parent `GITHUB_SHA` and reject missing attribution, either parent-SHA expression, a tutorial SHA, and checkout/build ref disagreement. The package config check and composition CI step run these tests. The final fresh source build ran with a foreign parent `GITHUB_SHA` and the composed browser verified API version 1 and WebGPU source `33366e270556c69201da901612cb522b4e18e2ee`. The new tutorial script also overrides inherited attribution with its validated exact ref. Do not change the upstream fetched script, fake the recorded SHA, or switch to release downloads. The embedded string is metadata; retain actual checkout hashes, clean-source verification, build logs and asset hashes as independent provenance.
